# ADR 0003 原生入口可见性与布局观测解耦

日期：2026-11-10。状态：0.1.4 采用；本次 Edge/开始菜单闪隐场景已由用户操作确认并对照运行日志完成闭环，详见 [验证记录](../verification.md)。

## 已确认的问题

0.1.3 的实际日志多次出现 `shown-cached-layout`、约三秒后的 `hidden-layout-unavailable`，以及稍后 `shown-measured`。这证明至少一条实际闪隐路径由应用自己的 UIA 数据超时规则主动隐藏窗口引起。它不是进程退出，也没有证据证明是 Edge 覆盖了入口。

之前把四秒读数新鲜度同时当作入口可见性租约，语义不正确。即使保留最后测量或识别离屏标志，完整 UIA 数据不可用超过期限后仍会回到同一故障路径。

## 决策

原生任务栏 HWND、原生边界、DPI、可见状态和用户开关决定已显示入口是否仍有有效上下文。UIA 仅用于提交新的布局证据；Unknown、旧观测、重复观测和暂时无数据不能单独清除同一原生上下文中的已确认入口。

只有新的完整可信测量才重新计算分配矩形。没有新证据时冻结最后实际分配的矩形和显示模式，不因金额或字幕长度变化扩大范围。新的可信无空间结果立即替换旧测量，且后续未知读数不能恢复旧安全布局。

四秒只用于判断一个候选更新是否足够新，不再使已分配位置到期。观测序号避免旧消息重放；当前原生检查优先于旧的后台“不可用”结果。原生隐藏、禁用或上下文变化仍立即失效，无历史数据时不猜位置。

Monitor 对自身进程的 UIA 子树剪枝，缓存匹配任务栏上下文的 frame；提供固定原因码、实际捕获耗时和序号。日志不得包含窗口标题、控件文本、薪资、用户输入或异常消息。

## 限制与验收

任务栏槽位仍不是 Explorer 正式预留的扩展区域。没有新数据时冻结原矩形能避免擅自扩张，但不能宣称绝对知道所有应用按钮是否重排；一旦取得新的可信布局必须及时更新或让位。

必须回放实际故障序列，并验证长时间 Unknown、旧结果重放、文字变宽、无空间反证、父窗重建和 DPI 变化。构建测试后需要用户切换 Edge 和开始菜单；核对用户观察及同一时间段日志，不能以测试数量代替实际闭环。
