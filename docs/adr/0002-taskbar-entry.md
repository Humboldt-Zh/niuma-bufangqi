# ADR 0002 单一任务栏入口

日期：2026-11-09。状态：采用；0.1.1 源码已实现，原生交互待用户人工验收。

本决策取代 [ADR 0001](0001-windows-host.md) 中“工作区浮动小挂件、不附着 Explorer 任务栏”的入口选择。Core、WPF、WebView2、本地状态和受限消息桥的技术选择继续保留。

## 背景

用户明确要求保留最底部任务栏内的原位置，将收益卡片的信息放进任务栏，点击打开新版面板，再点击关闭。0.1.0 的绿色浮动卡片不符合这一形态；旧工具与新版同时运行还会出现两个入口。

因此，仅调整浮窗位置或再创建一个桌面挂件不能满足当前要求。用户同时要求由自己操作电脑，开发过程只负责源码、测试、构建和安装包，不能代替用户退出程序、切换启动项或验证桌面。

## 决策

- 用 WinForms 分层子窗口承载任务栏入口，将其附着到 Explorer 主任务栏 `Shell_TrayWnd`。
- 使用任务栏布局信息和 UI Automation 边界寻找安全空位，沿用原入口所在区域；收益与简短状态在任务栏内呈现，不创建绿色浮窗。
- 入口不激活窗口。点击时根据面板可见状态切换，失焦处理识别入口命中区域，保证第二次点击确实关闭面板。
- WPF 和 WebView2 继续承载新版面板，面板贴近入口向上展开，并且不增加普通任务栏按钮。
- 系统托盘保留打开、设置和退出入口。无法安全挂接或空间不足时仅使用托盘，不覆盖系统按钮，也不回退到独立浮动卡片。
- Explorer 重建后重新定位并重建挂接；不重启 Explorer，不修改系统任务栏配置。
- 已配置启动只显示入口；首次未配置或用户显式使用 `--open` 时打开面板。检测到旧薪资时钟或另一安装目录占用同一配置时提示冲突，不创建第二个入口、不激活旧界面，也不自动结束旧进程。

## 代价与约束

`Shell_TrayWnd`、UI Automation 元素及 Explorer 的任务栏布局属于系统实现细节，不能当作长期稳定的第三方扩展契约。Windows 更新可能改变位置或层级；发生不确定情况时必须优先隐藏入口并保留托盘。

UI Automation 查询在后台进行并设置恢复边界，不能阻塞面板 UI。代码需要明确释放窗口、计时器、GDI 资源及监视任务。任务栏自动隐藏、不同 DPI、多显示器和 Explorer 重建必须逐项记录真实环境下的结果。

已通过的 Core 或浏览器测试不证明任务栏挂接已通过。此前绿色卡片截图也不能作为新模式的验收证据。

## 升级与验收

0.1.1 由用户手动退出旧薪资时钟和 0.1.0 浮窗版，解压新包并运行正确版本。启动冲突保护能拒绝继续叠加入口，但不会替用户清理已经同时运行的旧程序。快捷方式和自启动目标由用户主动确认；自启动开关反映当前 EXE 的实际注册状态。已有原生配置继续使用，不随安装包分发真实数据。

验收以 [手动升级与验收](../manual-upgrade.md) 为准，至少包含单入口、连续三次点击、失焦、`Esc`、托盘恢复、空间不足、自动隐藏、DPI 和 Explorer 重建。未完成的项目保持待验证，不以编译通过代替。
