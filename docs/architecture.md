# 牛马不放器架构与技术路线

日期：2026-11-09。状态：0.1.1 任务栏入口改造；具体构建与实测结果以 [验证记录](verification.md) 为准，新的原生交互仍待人工验收。

## 目标与选择

首版服务 Windows 工位场景：任务栏内只有一个收益入口，点击展开收益、下班时间、休息和情绪互动，再点击同一入口收起。采用 .NET 10 LTS、WPF 与 WebView2，复用现有网页交互，同时把系统集成与持久化放到原生端。宿主选择见 [ADR 0001](adr/0001-windows-host.md)，入口选择以 [ADR 0002](adr/0002-taskbar-entry.md) 为准。

界面不依赖 Web 服务器或远端服务，不引入账户、云同步、遥测或 AI 后端。0.1.1 根据用户明确要求，将入口子窗口附着到 Explorer 任务栏；这取代了 0.1.0 的工作区浮动卡片方案。

## 模块职责

`src/NiumaBufangqi.Core` 是纯 BCL 类库，处理工资设置校验、计薪状态和快照，以及版本化本地状态存储。金额采用 `decimal`；计算只接收明确的设置与本地时间，不读取系统 UI 或网页状态。

`src/NiumaBufangqi.Desktop` 是 Windows 宿主，负责单实例运行、窗口生命周期、任务栏入口、托盘、面板定位、开机启动、WebView2 初始化及受限消息桥。WinForms 承载任务栏子窗口及托盘，WPF 承载展开面板，WebView2 渲染面板内容。任务栏入口不再由独立的 `WidgetWindow` 浮窗承载。

根目录 HTML/CSS/JavaScript 是 UI 资产。`app.js` 管理界面和休息交互，`model.js` 支撑浏览器演示；桌面模式通过 `desktop-bridge.js` 使用宿主状态和真实计薪快照。`desktop.css` 去掉模拟桌面外壳，保留原面板与揉纸体验。`paper-play.js` 和本地 SVG 承载纸张互动，不持久化烦恼文字。

`tests/NiumaBufangqi.Core.Tests` 是无第三方测试框架依赖的控制台测试。网页测试位于 `tests/`；它们与 Core 测试分别运行，不能相互替代。

`scripts/` 提供构建与发布入口。发布时只复制必要界面资源到 `WebAssets/`，不复制仓库根目录、用户配置、调研原件或 WebView2 用户数据。

## 状态与时间

原生端持有持久状态和真实系统时间；网页负责呈现。首次状态的 `Settings` 为 `null`，界面进入设置，月薪空白；不能拿浏览器演示的虚构工资冒充用户配置。

设置保存的顺序是：网页提交候选值，宿主验证消息和工资规则，原子保存成功，宿主返回确认，网页再更新生效状态。失败保留原状态并显示可理解的错误。金额隐藏等持久偏好同样不能在保存失败时假报成功。

UI 和任务栏入口使用相同的原生快照，避免两处计薪规则漂移。演示模式独立保留可切换的虚构日期与场景，不污染原生状态。休息估算金额是正常计薪的一部分，不增加总工资。

## 本地存储

根目录为 `%LOCALAPPDATA%\NiumaBufangqi`：

- `state.json`：schema 1，保存工资设置、隐私偏好、自启动与入口显示偏好、已结束的休息记录。
- `state.json.bak`：最近可恢复的备份。
- `WebView2/`：独立的 WebView2 用户数据。

配置先序列化到同卷临时文件并刷新，再原子替换。主配置损坏时尝试备份；原文件保留，后续保存另存损坏副本。遇到不支持的 schema 立即拒绝读写，避免旧版本破坏新版本数据。

本地 JSON 不做应用级加密，也不上传。烦恼文字和揉纸会话计数不进入状态；关闭或完成交互后清空。配置大小与记录字段要有上限，异常内容不得变成无限增长或任意文件操作。

## 原生窗口与任务栏入口

入口是附着到主任务栏 `Shell_TrayWnd` 的子窗口，收益、状态与悬停反馈都位于任务栏区域内。通过 UI Automation 获取天气按钮与应用区边界，避免覆盖系统按钮。空间不足或无法确认位置时隐藏入口，保留托盘恢复路径；不创建绿色浮动卡片兜底。

展开面板目标尺寸为 560 × 760 DIP，锚定任务栏入口上方并限制在可用工作区内，短屏按可用尺寸收缩。面板不创建额外的普通任务栏按钮。

同一入口的第一次点击打开面板，第二次点击收起，第三次可再次打开。入口不能抢占面板激活状态；失焦处理必须识别鼠标是否仍在入口，避免“先失焦隐藏，再执行切换又打开”的竞态。普通页面 `Esc` 收起面板；有对话框时先关闭对话框。任务栏右键菜单和托盘菜单提供真正的退出。

已配置用户启动后只显示任务栏入口，不主动弹出面板；首次未配置时打开设置，命令行 `--open` 可明确要求显示面板。启动前检查旧 `SalaryClock` 进程和同一配置的其他安装目录实例，发生冲突时提示用户退出，不创建第二个入口，也不将激活请求发给另一目录的旧版本。程序不自动结束这些进程。

任务栏监视不得在 UI 线程执行可能阻塞的 UI Automation 查询。Explorer 重建后重新寻找主任务栏并挂接入口，不能依赖旧 HWND 或通过重启 Explorer 来恢复。内部布局和窗口承载方式不是稳定的应用扩展契约，Windows 更新、自动隐藏、DPI 与多显示器行为必须单独人工验收。

入口原生可见性与 UIA 数据新鲜度分离。已分配位置在同一原生上下文中持续保持，Unknown 或旧样本不能单独隐藏入口；等待新数据时冻结实际矩形，不因文字变宽扩大范围。新鲜可信的无空间证据和原生失效立即生效，详见 [ADR 0003](adr/0003-native-visibility-and-layout-observation.md)。

开机启动开关以当前 EXE 对应的实际启动项为准，不只读取持久状态中的偏好；换安装目录后不会假报已启用。开启时使用当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。无需管理员权限，不增加计划任务或服务。注册表变更和持久状态必须一致，失败向用户说明；旧软件或旧路径的启动项由用户主动确认并关闭。

## WebView2 与消息边界

仅将打包的 `WebAssets` 映射到 `https://niuma.app`，使用 `CoreWebView2HostResourceAccessKind.Deny` 禁止其他来源读取。该地址只在本地 WebView2 映射中解析，不是网络网站，也不需要本机监听端口。

消息桥在读取负载前检查来源，再检查已知消息类型、协议字段及具体值范围。未知消息、过大的负载、无效设置均拒绝。不给网页暴露任意命令、文件路径、脚本执行或通用宿主对象。

外部导航、iframe 导航和远端资源请求受限制；设备权限默认拒绝。用户明确点击的合法 HTTPS 外链由系统浏览器打开。JSON 消息使用序列化传输，不把用户文字拼接到脚本中。

WebView2 使用单独的本地 profile。Evergreen Runtime 由 Microsoft 维护；程序检测缺失并引导官方安装，不关闭证书或系统保护来掩盖部署失败。

## 构建与发布

SDK 由 `global.json` 固定为 10.0.403 功能带；WebView2 NuGet 版本固定为 1.0.4314.35，并保留锁文件。Node.js 24 用于网页检查与测试；网页无需运行时 npm 依赖。

`scripts/build.ps1` 是本地质量入口；CI 应使用固定版本或完整提交 SHA 的官方动作，在 Windows 上执行相同检查。Core 控制台测试必须实际运行，不以只构建测试项目代替。

`scripts/publish.ps1` 生成自包含 win-x64 目录、ZIP 和 SHA-256 文件。无需目标机另装 .NET，但仍需 WebView2 Runtime。发布包要保留本项目许可证、WebView2 SDK 的 LICENSE/NOTICE 及 .NET 随附声明。首版采用手动更新，代码签名和安装器后续单独完成。

普通构建使用 `packages.lock.json`，发布还原使用 `packages.win-x64.lock.json`，防止运行时标识符改变普通锁文件。版本源是 `Directory.Build.props`，构建会核对网页包版本一致，原生显示版本来自程序集。发布标签须存在且指向本次提交；发布包记录源码提交，不包含本项目 PDB。

## 分阶段路线与质量门槛

### 第一阶段 可验证的本地预览

完成 Core 校验和计算、原子配置、浏览器/原生模式分离、消息桥及最小宿主。门槛是 Core 与网页检查通过，未配置状态不出现虚构工资，保存失败不显示成功，未来 schema 不被覆盖。

### 第二阶段 Windows 可用版本

完成任务栏入口、托盘、展开面板、首次配置、真实快照和自启动。门槛是在真实 Windows 环境验证入口点击开关、失焦与 `Esc`、Explorer 重建后的恢复、关闭/退出、重新启动持久化、配置错误、WebView2 缺失引导、投纸中途退出和键盘操作。新任务栏模式尚未通过这些人工验收，不能沿用浮窗版截图或测试结论。

### 第三阶段 可复现的开源发布

完成干净目录构建、锁文件、CI、发布 ZIP、校验文件、第三方声明和文档。门槛是发布包在独立目录启动，仓库无个人配置、调研原件或凭据；GitHub 远端和下载链接只在实际创建后记录。

### 后续 增量兼容与分发

先补多显示器、DPI、任务栏自动隐藏及连续工作日试用，再考虑 arm64、安装器、签名与更新。每项分别给出验收结果；跨平台、云服务和复杂桌宠不进入首版必要范围。

## 升级与验证的操作者边界

开发阶段只修改源码、运行不触碰桌面的测试、构建和打包；退出旧程序、替换软件、启动新版、确认快捷方式和启动项，由用户手动执行。新软件不自动结束旧薪资时钟或 0.1.0 浮窗版，不接管旧进程，也不自动改写其他程序的自启动。

已有原生配置继续从 `%LOCALAPPDATA%\NiumaBufangqi` 读取。只要该配置已经迁移，不需要重填，也不把真实配置复制进安装包或仓库。[手动升级与验收](manual-upgrade.md) 给出具体步骤和需要用户反馈的结果。
