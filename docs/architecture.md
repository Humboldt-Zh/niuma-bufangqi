# 牛马不放器架构与技术路线

日期：2026-11-09。状态：首版 Windows 宿主实现阶段；具体构建与实测结果以 [验证记录](verification.md) 为准。

## 目标与选择

首版服务 Windows 工位场景：一个安静的小挂件，点击展开收益、下班时间、休息和情绪互动。采用 .NET 10 LTS、WPF 与 WebView2，复用现有网页交互，同时把系统集成与持久化放到原生端。决策理由见 [ADR 0001](adr/0001-windows-host.md)。

界面不依赖 Web 服务器或远端服务，不引入账户、云同步、遥测或 AI 后端。首版不使用 Explorer 私有任务栏注入。

## 模块职责

`src/NiumaBufangqi.Core` 是纯 BCL 类库，处理工资设置校验、计薪状态和快照，以及版本化本地状态存储。金额采用 `decimal`；计算只接收明确的设置与本地时间，不读取系统 UI 或网页状态。

`src/NiumaBufangqi.Desktop` 是 WPF 宿主，负责单实例运行、窗口生命周期、托盘、小挂件、工作区定位、开机启动、WebView2 初始化及受限消息桥。WinForms 仅用于系统托盘等 Windows 集成，不承担网页内容渲染。

根目录 HTML/CSS/JavaScript 是 UI 资产。`app.js` 管理界面和休息交互，`model.js` 支撑浏览器演示；桌面模式通过 `desktop-bridge.js` 使用宿主状态和真实计薪快照。`desktop.css` 去掉模拟桌面外壳，保留原面板与揉纸体验。`paper-play.js` 和本地 SVG 承载纸张互动，不持久化烦恼文字。

`tests/NiumaBufangqi.Core.Tests` 是无第三方测试框架依赖的控制台测试。网页测试位于 `tests/`；它们与 Core 测试分别运行，不能相互替代。

`scripts/` 提供构建与发布入口。发布时只复制必要界面资源到 `WebAssets/`，不复制仓库根目录、用户配置、调研原件或 WebView2 用户数据。

## 状态与时间

原生端持有持久状态和真实系统时间；网页负责呈现。首次状态的 `Settings` 为 `null`，界面进入设置，月薪空白；不能拿浏览器演示的虚构工资冒充用户配置。

设置保存的顺序是：网页提交候选值，宿主验证消息和工资规则，原子保存成功，宿主返回确认，网页再更新生效状态。失败保留原状态并显示可理解的错误。金额隐藏等持久偏好同样不能在保存失败时假报成功。

UI 和小挂件使用相同的原生快照，避免两处计薪规则漂移。演示模式独立保留可切换的虚构日期与场景，不污染原生状态。休息估算金额是正常计薪的一部分，不增加总工资。

## 本地存储

根目录为 `%LOCALAPPDATA%\NiumaBufangqi`：

- `state.json`：schema 1，保存工资设置、隐私偏好、自启动与挂件偏好、已结束的休息记录。
- `state.json.bak`：最近可恢复的备份。
- `WebView2/`：独立的 WebView2 用户数据。

配置先序列化到同卷临时文件并刷新，再原子替换。主配置损坏时尝试备份；原文件保留，后续保存另存损坏副本。遇到不支持的 schema 立即拒绝读写，避免旧版本破坏新版本数据。

本地 JSON 不做应用级加密，也不上传。烦恼文字和揉纸会话计数不进入状态；关闭或完成交互后清空。配置大小与记录字段要有上限，异常内容不得变成无限增长或任意文件操作。

## 原生窗口

小挂件目标尺寸为 224 × 51 DIP，展开面板目标尺寸为 560 × 760 DIP；短屏或较小工作区按可用尺寸收缩，内容独立滚动。

定位依据 Windows 工作区，避开系统任务栏占用区域。挂件位于工作区底部，点击向上展开面板；面板关闭后返回挂件。系统托盘提供恢复与退出入口，确保界面收起后仍有可找回的路径。

不把窗口设为 Explorer 的子窗口，不操作任务栏内部布局。多显示器、DPI、任务栏自动隐藏和全屏行为需要在 Windows 上实际验收，不能从单屏编译结果推断兼容。

开机启动默认关闭；开启时使用当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。无需管理员权限，不增加计划任务或服务。注册表变更和持久状态必须一致，失败向用户说明。

## WebView2 与消息边界

仅将打包的 `WebAssets` 映射到 `https://niuma.app`，使用 `CoreWebView2HostResourceAccessKind.Deny` 禁止其他来源读取。该地址只在本地 WebView2 映射中解析，不是网络网站，也不需要本机监听端口。

消息桥在读取负载前检查来源，再检查已知消息类型、协议字段及具体值范围。未知消息、过大的负载、无效设置均拒绝。不给网页暴露任意命令、文件路径、脚本执行或通用宿主对象。

外部导航、iframe 导航和远端资源请求受限制；设备权限默认拒绝。用户明确点击的合法 HTTPS 外链由系统浏览器打开。JSON 消息使用序列化传输，不把用户文字拼接到脚本中。

WebView2 使用单独的本地 profile。Evergreen Runtime 由 Microsoft 维护；程序检测缺失并引导官方安装，不关闭证书或系统保护来掩盖部署失败。

## 构建与发布

SDK 由 `global.json` 固定为 10.0.403 功能带；WebView2 NuGet 版本固定为 1.0.4314.35，并保留锁文件。Node.js 24 用于网页检查与测试；网页无需运行时 npm 依赖。

`scripts/build.ps1` 是本地质量入口；CI 应使用固定版本或完整提交 SHA 的官方动作，在 Windows 上执行相同检查。Core 控制台测试必须实际运行，不以只构建测试项目代替。

`scripts/publish.ps1` 生成自包含 win-x64 目录、ZIP 和 SHA-256 文件。无需目标机另装 .NET，但仍需 WebView2 Runtime。发布包要保留本项目许可证、WebView2 SDK 的 LICENSE/NOTICE 及 .NET 随附声明。首版采用手动更新，代码签名和安装器后续单独完成。

普通构建使用 `packages.lock.json`，发布还原使用 `packages.win-x64.lock.json`，防止运行时标识符改变普通锁文件。版本源是 `Directory.Build.props`，构建会核对网页包版本一致，原生显示版本来自程序集。发布标签须存在且指向本次提交；发布包记录源码提交，不包含本项目 PDB。

## 分阶段路线与质量门槛

### 第一阶段 可验证的本地预览

完成 Core 校验和计算、原子配置、浏览器/原生模式分离、消息桥及最小宿主。门槛是 Core 与网页检查通过，未配置状态不出现虚构工资，保存失败不显示成功，未来 schema 不被覆盖。

### 第二阶段 Windows 可用版本

完成挂件、托盘、展开面板、首次配置、真实快照和自启动。门槛是在真实 Windows 环境验证关闭/退出、重新启动持久化、配置错误、WebView2 缺失引导、投纸中途退出和键盘操作，记录实际设备与未覆盖项。

### 第三阶段 可复现的开源发布

完成干净目录构建、锁文件、CI、发布 ZIP、校验文件、第三方声明和文档。门槛是发布包在独立目录启动，仓库无个人配置、调研原件或凭据；GitHub 远端和下载链接只在实际创建后记录。

### 后续 增量兼容与分发

先补多显示器、DPI、任务栏自动隐藏及连续工作日试用，再考虑 arm64、安装器、签名与更新。每项分别给出验收结果；跨平台、云服务和复杂桌宠不进入首版必要范围。
