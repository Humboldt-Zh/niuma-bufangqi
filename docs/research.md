# 打工族安慰工具：轻量调研与原型决策

调研日期：2026-11-09  
状态：公开资料调研与设计假设，**尚未进行真人访谈或效果验证**。本文为本次高保真交互原型的中间产物。

## 已确定的方向

用户选择的核心场景是：工作烦、想放弃时，看一眼工资增长和下班倒计时，缓一口气。

- 形态：保留桌面小挂件，点击展开完整面板，先面向 Windows。
- 语气：幽默、打工人自嘲，可有摸鱼统计、情绪按钮和小彩蛋。
- 最终目标：在 GitHub 开源；本轮先通过可点击原型确认体验。
- 现有基础：本地已定位 SalaryClock，采用 C# / .NET 8，具备桌面窗口基础；原型确认后可考虑沿用，无需因为界面重设计而立即换技术栈。

建议的产品承诺：**烦的时候看一眼，钱在涨，下班在靠近，还有一句替你吐槽的话。** 这是待验证的定位，不是已证实的用户需求结论。

## 证据与限制

本轮只使用产品作者维护的 GitHub 仓库、README 和实际许可证文件作为一手来源。可以核实项目公开存在、作者描述的功能及公开许可文字；未安装运行竞品，未审核其全部源码，因此功能表现、离线程度、数据收集承诺均不能当作独立实测。没有把星数、作者宣传或截图作为情绪改善效果的证据。

许可证记录只描述本次可读取的状态，不构成对代码、模型、图片、字体等全部素材的授权审查。本轮原型采用原创界面和文案，不复用竞品代码或宠物素材。

## 差异化决策

公开项目已经覆盖“钱在涨”“倒计时”和“桌宠”这些元素。因此，本项目的差异化假设应放在**烦的时候能立即得到回应，以及在办公室足够低调**，而不是增加更多卡片。

1. **一眼有用**：小挂件只承担今日估算收益和距离下班两件事。点击后再展示生活目标、情绪回应和休息入口。
2. **吐槽站在用户一边**：回应具体情绪，不责备摸鱼，不把委屈都归因为用户不够积极。示例语气：“需求可以再改，你先喝口水。”
3. **随时收得住**：一键折叠、一键隐藏金额，动效和提醒有开关；屏幕分享场景值得单独验证。
4. **开源容易参与**：优先本地配置与离线文案，文案包可贡献；第一版不依赖账号、云服务或付费 AI API。这是范围决策，后续是否引入 AI 另行验证。

工资数字是根据用户配置得出的估算值，不应暗示已经实际到账。加班后应尊重用户设置，不自动把继续工作包装为奖励。

## MVP 交互范围

### 必须覆盖的完整路径

1. **首次设置**：填写估算工资、工作日和上下班/午休时段；能看懂收益计算口径。
2. **常驻挂件**：收益随时间更新，展示下班倒计时；点击展开，关闭后回到挂件。
3. **展开面板**：收益、下班进度、一个自选生活目标保持清晰主次。
4. **情绪回应**：点击“有点烦 / 想摆烂 / 还撑得住”，立即出现对应幽默短句；可以换一句或退出。
5. **带薪喘口气**：用户主动开始，显示本次时长和估算收益，可随时结束；不与工作效率排名关联。
6. **隐私与安静**：隐藏金额、控制动效、收起面板；设置保存并在下次恢复。
7. **下班状态**：时间到后出现明确收尾体验，例如“今天辛苦了，该你生活了”；无需继续完成任务。

### 本轮原型的边界

HTML 原型用于验证布局、语气、设置与交互闭环。置顶、鼠标穿透、系统托盘、自启动等桌面系统能力只在说明中记录，不把浏览器模拟表现宣称为已经实现的 Windows 能力。示例薪资与时间用于演示，应可辨认。

第一版暂缓：账号、同步、社交排名、社区吐槽流、任务管理、复杂养成和 AI 聊天。这些内容增加维护成本，且本轮没有证据证明它们是核心价值。

## 五个待验证用户问题

1. 最近一次上班特别烦时发生了什么？你当时实际做了什么，多久后缓过来？
2. 看见估算工资上涨，会让你舒服一点、没感觉，还是更在意工资低或时间流失？请结合一次真实经历说明。
3. 你在工作电脑上愿意常驻多大的挂件？开会、录屏、远程协作时通常怎样处理屏幕上的个人内容？
4. 面对几句具体吐槽，你觉得哪句贴心、哪句尴尬或刺耳？什么情况下你会把它关掉？
5. 下班后仍要工作、午休不计薪或工作时间不固定时，你希望工具怎样显示？哪些数字必须解释清楚才会信任？

## 可执行验证方案

以下数量、阈值均是**拟定的验证规则，不是现成研究结果**。

### 第一轮：5 人，约 25 分钟/人

招募有固定工时、在 Windows 电脑上工作的 5 位目标用户；尽量包括经常开会/共享屏幕、偶有加班和对打工梗接受度不同的人。

- 前 8 分钟：围绕上述问题询问最近的真实事件，先不展示产品，不问“你会不会喜欢”。
- 中间 12 分钟：无讲解展示原型，让用户完成首次设置、找到下班时间、点情绪按钮、开始并结束休息、隐藏金额、收起面板。
- 最后 5 分钟：逐句评价文案，选择愿意常驻的尺寸，指出最想删的功能。

记录任务是否独立完成、首次误点、完成时间、敏感信息顾虑和原话。5 人测试用于发现问题，不能代表总体比例。

拟定继续条件：至少 4 人能独立完成“展开—看懂—回应—收起”的核心路径；至少 3 人能结合真实场景说明愿意何时再打开。若收益数字让 2 人或以上更烦躁，优先提供倒计时优先和隐藏收益两种模式，再测。

### 第二轮：3 人，连续 3 个工作日

原生可用版本具备常驻能力后再进行；浏览器原型不能替代真实桌面占用测试。用户保留随时退出的权利，不要求每天完成次数。

每天只做一次简短回访：有没有主动打开、当时发生什么、哪一项帮上忙、有没有打扰，以及为什么关掉。无需收集实际薪资或键盘内容。

拟定决策：若 3 人中至少 2 人在两个不同工作日主动用于同类烦躁场景，且没有持续打扰反馈，则继续打磨该路径；否则根据访谈缩减或调整定位。无需先追求文案数量、养成系统或使用时长。

- 原创素材清单、第三方依赖及各自许可记录；项目许可证单独确定。
- 简明运行与构建步骤、贡献指南、可独立贡献的文案文件。

本轮结论：先验证“少量信息 + 一次及时回应”是否有用，再决定是否扩展成更大的桌面陪伴产品。
