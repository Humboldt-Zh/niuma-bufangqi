# 原型规格与验收

> 这是浏览器原型阶段的历史规格。当前 Windows 软件的技术路线以 [架构说明](architecture.md) 和 [ADR 0001](adr/0001-windows-host.md) 为准，实际验证情况以 [验证记录](verification.md) 为准。

版本：0.1.0  
日期：2026-11-09  
用途：评审桌面安慰小挂件的高保真交互，作为后续 Windows 实现的依据。

## 用户与核心路径

面向在电脑前工作、偶尔烦躁且想得到轻量安慰的打工族。已经确定的表达方向是幽默自嘲；不以增加产出或延长工作时间为目标。

核心路径：**看见左下角收益入口 → 点击在入口上方展开 → 表达情绪或休息一下 → 得到即时反馈 → 收起，再点入口原位展开。**

本轮尚未进行真人访谈。定位、文案接受度和常驻意愿都需要按 [调研方案](research.md) 验证。

## 实现范围

- `today`：今日估算收益、参考时薪、下班倒计时、计薪进度与情绪短句。
- `break`：手动选择 3 / 5 / 10 分钟轻提醒；开始、到点提示、主动结束、当日历史和清除。
- `feel`：四类情绪、对应短句切换，以及“写烦恼—揉纸—投篓—回应”的完整烦恼回收站。
- `settings`：工资、月计薪日、工作及午休时段、每周工作日；字段校验、保存、恢复演示设置。
- 全局：金额隐藏、面板收起/展开、计算说明、调研说明、演示与真实时间切换。

窗口和任务栏均为页面内模拟。托盘、置顶、穿透、自启动、原生快捷键、系统通知和安装包不在当前已实现范围。

## 布局与触发关系

完整面板锚定页面左下角收益入口上方，约 560px 宽，底部紧贴模拟任务栏；宽屏保持左下锚定，不再居中。窄屏按可用宽度收缩，面板不超出视口。

原左侧导航改为顶部四项页签。页签固定，四页内容采用紧凑单列或窄双列布局，并在面板内独立滚动。收起仅隐藏完整面板，底栏入口保留；再次点击入口在同一锚点展开。

## 交互验收

建议先以 `npm start` 启动，在现代桌面浏览器完成以下步骤。清单用于逐项验收，不代表已全部执行通过。需要清洁演示环境时，用新浏览器配置或恢复演示设置；不要输入真实薪资。

### 0. 左下角展开布局

- 宽屏打开时，面板位于左下角收益入口上方、紧贴底栏，不回到页面中央。
- 缩窄窗口后，面板宽度适应可用空间，无横向溢出，顶部操作和底栏入口均可触达。
- 四项页签始终可见；滚动设置或历史内容时，只滚动内容区，不把页签和底栏入口滚出视野。
- 四个页面均在同一面板范围内展示，单列或窄双列不会遮挡金额、时间、字段及操作按钮。
- 收起后点左下角底栏收益入口，面板在同一位置重新展开，当前计薪状态和页面交互仍可继续。

### 1. 首屏与场景

- 首次加载明确标注演示；金额和倒计时随时间更新。
- 切到午休，开启午休扣除时收益暂停；下班后收益封顶；休息日显示自由时间、当日收益归零。
- 切到本机实时时间，日期与状态取当前设备时间和已保存排班。
- 修改工作日和时段后，演示场景适应排班；关闭午休时午休场景不可选，每天均为工作日时休息日场景不可选。

### 2. 情绪与烦恼回收站

- 四个情绪按钮能表达当前选中状态，并更新对应短句。
- “换一句”可连续切换，不离开当前页面；页面间使用同一份当前情绪。
- 回收站在左下角原面板位置打开，输入、揉纸、投篓与结果均留在该范围内。
- 可输入最多 120 个 UTF-16 代码单元的文字、选择预设，或留空直接开始；不要求先写内容。
- “开始揉纸”算第一次点击，再点击两次，纸张分三步皱成原创 SVG 纸团；未揉完不能提前投篓。
- 可将纸团拖进纸篓；未投中时纸团回弹，保留重试机会。也可通过键盘聚焦并触发“帮我丢进去”，无需拖拽即可完成。
- 成功投中后播放落篓动画并显示回应；可选“再来一张”“开始 5 分钟休息”或“回去慢慢来”。
- “开始 5 分钟休息”实际进入现有休息页并启动 5 分钟计时；已有休息进行中时继续已有计时，避免重复创建。
- 丢纸张数只在回收站本次打开期间累计，不写入历史。输入文字不保存、不上传，完成或关闭立即清空。
- 回收站顶部关闭及 `Escape` 均可退出；退出会清理动画计时，返回后不应出现延迟跳转或残留动画。

### 3. 休息计时

- 未开始时可切换 3 / 5 / 10 分钟；开始后按真实经过时间计时，时长选择暂时禁用。
- 到点仅轻提示，不强制结束；“我歇好了”或结束按钮将记录写入本地历史。
- 计薪时段中的休息展示估算收益，并明确已包含在今日收益中；午休、下班或休息日不累计相应时段收益。
- 当日累计时长和次数随记录更新；“清除今天记录”只清当前日期及当前演示/真实来源的记录。
- 切换时间场景或保存排班会先结束当前休息，避免把两个不同时间轴或计薪口径混在同一条记录中。

### 4. 设置与持久化

- 月计薪日接受小数，例如自定义折算天数；工资与计薪日必须为有限正数，工资上限为 10,000,000 元，计薪日上限为 31 天。
- 无工作日、无效时间、下班不晚于上班、午休超出工作时段、午休倒置或扣除后没有计薪时间，均显示具体字段错误且不保存。
- 保存合法设置后立即更新计算；刷新后恢复配置。恢复演示设置后使用虚构默认值。
- 浏览器无法持久存储时仍能在会话中使用，并在保存操作时说明存储限制。

### 5. 收起与隐私

- 隐藏金额后，主页、参考时薪、休息估算、历史记录和底部挂件都遮住金额；刷新后保留选择。
- 顶部关闭/最小化或收起入口将完整面板隐藏，左下角底栏收益入口保留；点击后在入口上方原位展开。
- `Escape` 优先退出已打开的烦恼回收站或关闭场景菜单；一般页面状态下可收起面板。
- 页面常用按钮有可辨认名称，键盘操作具备焦点反馈；对话框可关闭并返回操作。

## 计算口径

模型在 `model.js` 中独立实现。

```text
参考日薪 = 月薪 ÷ 月计薪日
当日净计薪时间 = 下班时间 − 上班时间 − 已启用的午休时长
参考时薪 = 参考日薪 ÷ 当日净计薪小时数
今日已赚 = 参考日薪 × 已过计薪时间 ÷ 当日净计薪时间
计薪进度 = 已过计薪时间 ÷ 当日净计薪时间
```

上班前为零；工作日只累计工作区间内的计薪时间；午休扣除开启时冻结；下班后封顶为参考日薪；未选中的每周工作日归零。金额显示至分，模型保留完整时间用于比例计算。

“距下班”按时钟时间倒数，包含尚未经过的午休；计薪进度按净计薪时间计算，因此二者不应强求相同比例。月计薪日是用户自填折算参数，不会根据实际日历自动重算。

休息期间收益按休息区间与已配置计薪时段的交集估算，支持区间跨日拆分；其作用是说明这段时间对应的工资份额，不能再次加到今日总收益。休息开始时保存一份计薪配置快照。

## 时间、数据与限制

- 默认展示虚构的 2026-11-09 演示时间；演示时钟继续前进，不是实际考勤。切换到本机模式才使用设备当前时间。
- 所有日期按设备本地时区解释，未提供跨时区切换。模型不支持跨夜班；计薪区间跨日统计不代表已支持夜班排班。
- 不含税费、社保、请假、奖金、节假日调休和加班费，不连接银行或工资系统。
- 设置、隐私开关及已结束休息记录存于浏览器 `localStorage`；演示/真实记录按来源和日期区分，最多保留 100 条，当前日展示最近 8 条。
- 烦恼回收站的文字和丢纸计数不持久化、不上传；文字在完成或关闭时清空，计数在退出本次回收站后清空。
- 正在进行的休息仅在内存中，刷新或关闭页面不会自动补录。系统时钟被人工调整可能影响计时；长时间挂起后刷新当前显示，不应视为经过审计的工时系统。
- 直接从 `file://` 打开时，持久化取决于浏览器策略；推荐使用本地服务。无登录、自动联网、埋点或 AI 聊天，调研外链按用户点击打开。

## 验证方式

```sh
npm run check
npm test
```

语法检查覆盖交互脚本（含新增 `paper-play.js`）、模型和本地服务。回收站另使用 `paper-play.css` 与原创 `assets/crumpled-paper.svg`。11 项自动化测试覆盖：默认配置及浏览器暴露、上班前、工作中计薪与时钟区分、午休冻结及恢复、下班封顶、工作日选择、关闭午休、跨夜班拒绝、数值/工作日校验、金额及计薪日上限、时间和午休区间校验。

自动化测试集中于计薪模型，尚未覆盖完整浏览器交互、休息收益区间算法或真实 Windows 窗口能力。发布前应按上面的交互清单手动验收，并记录浏览器版本和结果；不把测试通过等同于用户价值已验证。

## 后续 Windows 实现

优先沿用 .NET 8 / WinForms + WPF，现有桌面工具本轮未修改。

1. 将计薪模型及边界用例映射到 C#，先对照同一组虚构输入保证结果一致。
2. 实现真实的小窗口与左下角展开面板，保留收益入口到上方面板的锚定关系；明确入口采用悬浮窗还是任务栏接入，再验证高 DPI、多显示器和全屏/共享屏幕场景。
3. 逐项接入托盘、置顶、穿透、全局快捷键与自启动；穿透状态必须保留可恢复操作的入口，自启动由用户主动开启。
4. 配置迁移到本地应用数据目录，提供版本号、无效配置兜底与清除数据入口；避免记录实际键盘内容。
5. 再用连续工作日试用验证打扰程度、文案接受度和主动打开场景，之后决定是否增加提醒或角色能力。
